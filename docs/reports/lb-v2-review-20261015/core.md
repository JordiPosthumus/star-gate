## Review

### Correct (verified, with evidence)

- **Cold-lane honesty holds.** `speedAt` returns `{tokensPerSecond: null, evidence: 'cold'}` for unmeasured lanes (routing-v2.mjs:186-188); `candidate()` nulls `completionSeconds` for cold lanes (routing-v2.mjs:240); cold lanes are never ranked by an invented number — they are chosen capacity-first, then as one bounded probe with `probed` set at the choice (routing-v2.mjs:290-298). Test S5 pins this.
- **EWMA normalization and per-level refinement are sound.** `soloEquivalent = rate / 0.9^(c−1)` (routing-v2.mjs:166-168) matches the approved curve in routing-estimates.mjs (`0.9 ** (concurrency − reference)`, the labelled seeded/borrowed tiers). The slowdown refinement uses the **pre-update** solo as reference (routing-v2.mjs:169-174), so there is no same-sample circularity. Hand-check of the test's example: 100 solo, then 180 tok/s at c=2 → solo EWMA 130, measured slowdown EWMA 0.9→1.17, composite 152.1 > 130 with evidence `measured_slowdown` — all correct. A known and acceptable property: a lane measured only at level *c* carries zero slowdown information beyond the default curve (the product solo×factor is what is identifiable); the composite at the measured level stays correct.
- **The hysteresis double-counting comment is TRUE.** `workOf(job)` includes `inputTokens` and `finishEstimate` divides by the lane's blended measured rate (which includes prefill time), so the destination's cold prefill *for this request* is already inside its finish estimate; `rehomeCost` (routing-v2.mjs:263-268) prices only the next turn's re-prefill. Adding the destination's input a second time would indeed double-count.
- **No thrash pathology.** A move requires the destination to beat the home by `max(hysteresis, rehomeCost)` (routing-v2.mjs:269,273); a revisit cycle would require A<B and B<A simultaneously — impossible. No unconditional stay-forever: home-full overflow bypasses the threshold (routing-v2.mjs:281-282), and the crowded-home test shows big work leaves a 3/4-busy home while tiny work honestly stays.
- **Clock-domain separation is correct everywhere except the one bug below.** `record` persists wall-clock seconds (`at = this.wallNow()`, routing-v2.mjs:158); `lastAt`/`updatedAt` are compared only against `wallNow` (routing-v2.mjs:292-295); `dispatchedMono` is never persisted, so no stale monotonic timestamp can meet a new process's clock after restart.
- **Persistence mechanics other than the loop bug are right:** temp file opened `'wx'` 0o600, `handle.sync()`, then rename (routing-v2.mjs:335-338); corrupt file preserved via timestamped `.corrupt-` rename with a user-facing notice (routing-v2.mjs:112-118, test covers it); unknown format ignored; malformed lane rows and non-finite JSON values dropped by `restoreSample` (routing-v2.mjs:124-125,143-152); `storageError` freezes writes and is surfaced in `status()` (routing-v2.mjs:322-323,345-347).
- **Measurement hook is honest in provenance:** only `outcome==='complete'` with integer, positive usage records a sample (gateway.mjs:1218-1221); faulted/cancelled requests are excluded (fault rewrites the outcome before the hook, gateway.mjs:1176-1177); identity comes from `routingWorker(node)` so an engine/model swap resets the lane (routing-v2.mjs:135-141, test covers).
- **Concurrency choice is more correct than the reviewed artifact** (see P2-5): the module prices the incoming request at its actual post-join concurrency `running.length + 1` capped at capacity (routing-v2.mjs:218-222), which is what the design's prose intends ("a spare slot starts at zero delay", "empty lane scores work/solo").

### Findings

**P1-1 — Persistence is write-once per process: `this.writing` is never cleared, so every save after the first write cycle is silently dropped.**
- Location: ds4-gateway/routing-v2.mjs:322-347 (`save`), 349 (`flush`), 351-354 (`close`).
- Evidence: `save()` assigns `this.writing = (async () => { while (this.dirty) {...} })().catch(...)` (routing-v2.mjs:326) with **no `.finally` reset**. After the loop drains, `this.writing` remains a resolved (truthy) promise, so line 325's `if (this.writing) return;` makes every later `save()` set `dirty = true` and return without writing — `dirty` then stays true forever. `flush()` (line 349) returns the already-resolved promise, so it reports success while later records are unflushed. `close()` sets `closed = true` **then** calls `save()`, which early-returns on `closed` (line 323) — the commented "final coalesced flush" never executes. The legacy pattern this was modeled on does it correctly: routing-observations.mjs:667-668 ends with `.finally(() => {this.writing = null; if (this.dirty && !this.state.storageError) this.save();})`. The test suite masks this because its persistence test issues both records inside the *first* write cycle and flushes once; no test performs record→flush→record→flush→reload.
- Impact: `lane-speeds.json` receives exactly one snapshot per process lifetime (state at the first quiet moment after startup). All subsequent EWMA refinement is memory-only and lost at restart, after which the module re-serves the stale first-snapshot numbers **labelled `measured`** — defeating the stated cutover premise ("builds each lane's number from real traffic before any cutover"). Measurement runs live today (`routing_time_enabled: true`, config.local.json:534), so this is active now, not dormant.
- Remedy: mirror the legacy tail — `.finally(() => {this.writing = false; if (this.dirty && !this.closed && !this.state.storageError) this.save();})` — make `close()` await in-flight writes (`async close() {this.closed = true; while (this.writing) await this.writing;}`; note the gateway currently never calls `close`/`flush` at all), and add the second-write persistence test.

**P1-2 — Unit mismatch: `dispatchedMono` is milliseconds, `at` is seconds; running-work decay never engages in production.**
- Location: routing-v2.mjs:63-66 (`remainingSecondsOf`), 78 (`now = () => performance.now() / 1000`), 232 (`at = this.now()` default); gateway.mjs:644 and 660 (both `evaluate` call sites pass no `at`); gateway.mjs:452 and 1211 (`job.dispatchedMono` is a `performance.now()` **ms** timestamp).
- Evidence: gateway running entries are raw job spreads with no `elapsedSeconds` (gateway.mjs:621-627), so production always takes the `dispatchedMono` branch: `Math.max(0, (at − entry.dispatchedMono) / 1000)` where `at ≈ dispatchedMono/1000` ⇒ the difference is ≈ −dispatchedMono ⇒ always clamps to 0. The constructor comment ("`now` … matches dispatchedMono for elapsed work", routing-v2.mjs:82-85) is right about the epoch and wrong about the unit. Tests always pass `elapsedSeconds` directly, so they never exercise this path.
- Impact: `pendingSeconds` counts every running request at its full total for its entire life; a full 4-slot lane running long jobs reports hours of phantom drain instead of the decayed remainder. Home-full `startDelay` and `waitingSeconds` are grossly overstated, overflow (`available_capacity_fallback`) fires far earlier than the reviewed Design C v2 intends, and the "running work decays" property exists only in tests. It also corrupts the shadow `agree/disagree` tallies (gateway.mjs:663-665) that are meant to justify cutover.
- Remedy: treat `dispatchedMono` as ms — `Math.max(0, (at * 1000 - entry.dispatchedMono) / 1000)` — and add a test whose running entries carry `dispatchedMono` with the default `now()`.

**P1-3 — Measurement counts cached prompt tokens as engine work, deviating from the reviewed definition (`prompt−cached+completion`) and biasing placement toward cache-warm lanes for cold work.**
- Location: gateway.mjs:1219-1221 (`tokens: observer.usage.prompt_tokens + observer.usage.completion_tokens`); docs/reports/lb-design-c2-offline.mjs line ~14 ("speed(L) — measured blended tokens per service second (prompt−cached+completion tokens / service seconds)"); `observer.usage.cached_tokens` is already normalized and available (gateway.mjs:306-311).
- Evidence: the reviewed design explicitly subtracts cached tokens; the implementation does not. On this conversation-affine fleet (durable per-conversation homes, cache-continuity as a first-class subsystem), a warm request with e.g. 90% of its prompt cached reports ~7-10× the computed-work rate. Because `workOf` also counts full input, estimates are calibrated to each lane's *average* cache mix — self-consistent for average traffic, but systematically optimistic (by roughly the cache-inflation factor) for colder-than-average jobs: new conversations and post-move turns. `rehomeCost` uses the same inflated `solo` (routing-v2.mjs:263-268), under-pricing re-homing. All of this is presented under the `measured` evidence label.
- Remedy: subtract reported cached tokens in the hook (`Math.max(0, prompt − (cached ?? 0)) + completion`) and make `workOf` consistent (subtract the job's per-destination reusable input when known, as the legacy planner's `inputEstimate` did), or explicitly document the mix-calibration in the module header and evidence labels. Decide **before** the measurement campaign accumulates history — changing the token definition later invalidates or mixes prior samples inside one EWMA.

**P1-4 — `workOf` estimates input from raw body bytes (`bytes/4`); for multimodal bodies this invents ~10⁶ phantom tokens, which the codebase's own metadata layer refuses.**
- Location: routing-v2.mjs:53-57 (`requestBytes ? Math.ceil(job.requestBytes / 4)`); gateway.mjs:1151 (`job.requestBytes` = raw request-body bytes, accumulated for every job); routing-observations.mjs:60 (`inputTokens: routable && !multimodal ? Math.ceil(byteLength/4) : null` — the gateway's own judgment that bytes/4 is invalid for multimodal).
- Evidence: gateway jobs carry `requestBytes` but not `inputTokens` (that lives in `job.routingInput.inputTokens`, null for multimodal per routing-observations.mjs:60-61). A single vision request with a multi-MB base64 body contributes ~1M+ phantom "input tokens" to `pendingSeconds`/`startDelay` (full lanes with image work look busy for hours, so v2 refuses to overflow into them) and to `rehomeCost` (a vision job gets a move threshold of hours — stay-forever on any home with a spare slot). Reachable whenever vision traffic meets a full lane.
- Remedy: prefer `job.routingInput?.inputTokens`; when metadata exists with `inputTokens === null` (multimodal), treat input as unknown (zero input + labelled median output) instead of falling through to `requestBytes`.

**P2-1 — Receipt `at` switches clock domain vs the legacy receipt shape.** routing-v2.mjs:248 `at: Math.round(at * 1000)` is performance-epoch ms; legacy summaries use `Date.now()` (routing-observations.mjs:110,608). No current consumer renders v2's `at` (the LB panel reads `routing_time.last`; `routingV2Shadow.last` correctly uses `Date.now()`, gateway.mjs:666), but the module's claim "same receipt shape … consumed unchanged" is false for this field; any future consumer renders a 1970 timestamp. Remedy: `at: Math.round(this.wallNow() * 1000)`.

**P2-2 — The "passive" shadow comparison mutates durable state.** With `routing_v2_enabled=false` (config.local.json:543), every legacy evaluation runs `recordRoutingV2Shadow` → `evaluate`, whose cold path sets `probed` and persists (routing-v2.mjs:298,181). Harmless today (restart precedes any flag flip and P2-3 drops these flags anyway), but a passive comparison should not write state. Remedy: gate the probe mutation on a decisions-enabled flag passed from the gateway, or document it.

**P2-3 — The probe bound does not survive restarts for never-measured lanes, and `probeAfterSeconds` never applies to them.** `load()` drops any lane without a valid solo sample (`if (!solo) continue`, routing-v2.mjs:124-125), discarding the persisted `probed: true` of a probed-but-still-cold lane; and `lastAt` is null for never-measured lanes, so `last === null ||` short-circuits the idle wait (routing-v2.mjs:294-295) — the reviewed "one bounded probe after `probeAfterSeconds` idle" is effectively "one probe per process, immediately" (the idle threshold only gates re-probes after an identity swap, where `lastAt` survives the reset). Remedy: persist cold-lane probe state in a separate top-level map (or document), and decide whether never-measured lanes should wait for idle.

**P2-4 — Evidence label `measured` over-claims for the normalized solo.** `speedAt(id, 1)` returns `evidence: 'measured'` even when every sample came from higher concurrency, where solo is `rate / 0.9^(c−1)` — a default-curve-normalized value, not a direct solo measurement; `soloSamples` counts all levels. Cross-level extrapolations inherit the default-curve bias while labelled `measured` (e.g., a lane measured only at c=4 with a true factor of 0.5 reports solo ~69% high). The composite at the measured level remains correct. Remedy: label the derivation (e.g., `measured_normalized` plus the levels it was derived from) or track measured levels in `status()`.

**P2-5 — The shipped concurrency term deviates from the reviewed offline artifact.** Offline doc: `Math.min(capacity, running.length + Math.max(1, spare))` — which equals `capacity` whenever any slot is free (an empty 4-cap lane priced at c=4, contradicting the doc's own "empty lane scores work/speed" prose). Module: `Math.max(1, Math.min(capacity, running.length + 1))` (routing-v2.mjs:220-222) — the physically correct post-join concurrency. The module is right and the doc's formula is likely a typo, but the reviewed artifact and the shipped rule disagree. Remedy: fix the doc's formula to `running.length + 1` so the offline review matches what ships.

**P2-6 — Home-full overflow moves unconditionally.** routing-v2.mjs:281-282 does not require `best.completionSeconds < home.completionSeconds` (`savingSeconds` honestly reports 0 when worse). This matches legacy semantics (routing-plan.mjs:160-163 sorts by load, not finish, when the home can't start), so it is inherited rather than a regression — but a one-line guard would prevent overflow to a strictly worse finish.

**P2-7 — Cold-lane tie-break is array order.** `withSlot[0]` and the probe `find` iterate the workers array (`[home, …others]`, gateway.mjs:621), so with several cold lanes the probe/capacity choice depends on node ordering rather than the `localeCompare` tiebreak used for measured lanes (routing-v2.mjs:257). Remedy: sort `withSlot` by id before selection.

**P2-8 — UI copy mislabels the v2 `no_capacity` stay.** ui/routing-observation.js v2 stay default renders "Stayed: the assigned worker has the best measured estimated finish." when the actual reason is `no_capacity` (full home, no measured peer with a slot, no cold slot — reachable via routing-v2.mjs:288-289). Remedy: add a `no_capacity` branch. (The v2 `saving_exceeds_hysteresis` stay branch is dead code — that reason only accompanies reassign.)

### Missing tests that matter (task item 5)

1. **Second-write persistence**: record → `flush()` → record → `flush()` → new instance → assert the second update is on disk. This is the test that exposes P1-1; without it the suite certifies a broken mechanism.
2. **`dispatchedMono` elapsed decay**: running entries carrying `dispatchedMono` (performance-epoch ms) evaluated with the default `now()`; assert pending decays with elapsed. Exposes P1-2.
3. **Cached-token semantics**: a record with `cached_tokens > 0` pinning whether cached prompt tokens count as work (currently undefined behavior — P1-3).
4. **Multimodal/unknown input on running entries**: a running entry with a large `requestBytes` and no parseable input must not produce phantom pending work (P1-4).
5. **Overflow comparison**: home full and about to drain vs a slower idle peer — pin whether v2 moves (currently unspecified, P2-6).
6. **Shadow purity**: with decisions disabled, `evaluate` must not flip `probed` or persist (P2-2).
7. Probe restart behavior for a still-cold lane (P2-3) — cheap to add once P1-1's fix lands.

### Verified non-issues (asked for explicitly)

- Remaining-seconds circularity: none within a sample (reference is the pre-update solo, routing-v2.mjs:169-171); the design-level feedback loop (decisions shape traffic shapes measurements) is damped by EWMA + hysteresis + the bounded probe.
- Restart safety of clocks: `dispatchedMono` is never persisted, `lastAt`/`updatedAt` are wall seconds and only compared to `wallNow` — no cross-restart mono/wall mixing. (P1-1/P2-3 are the actual restart defects.)
- Corrupt-file preservation, unknown-format handling, and atomic temp+rename+file-fsync are correct; only a directory fsync is absent (same gap as the legacy store — accepted repo pattern, not flagged).
