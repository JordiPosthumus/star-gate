## 1) System understanding

Each worker owns `slots[]` (active request per slot, up to `max_concurrent_requests`, possibly capped by detected engine execution capacity) plus a sequence-ordered queue. `AffinityStore` durably maps SHA-256 conversation keys → home worker; admission gives the warm home first refusal, falls back to `placementChoice` (load-per-capacity, then session-count spread), and parks unplaceable work with patient-wait deadlines (`deadline.mjs` chains timers past Node's 2³¹−1 ms clamp). `queue-choice.mjs` is the single chooser shared by the real dispatcher and the forecast: priority rank (idle-only < normal < high < genie), per-conversation head-of-line, turn reservations with grace, priority override, exhausted-turn yield. The time-based router (`routing-plan.mjs`) forecasts each candidate's completion by booking pending work into slots (`completionEstimate`) and moves only when saving > switching margin through a synchronous compare-and-commit that persists ownership first. `routing-estimates.mjs` supplies the math: log-normal output-length fit with conditional, limit-truncated remaining tokens; per-concurrency phase-speed medians with observed→seeded→borrowed evidence tiers; cache-adjusted input. `RoutingObservations` feeds it: per-request engine rows (vLLM idle-serial attribution, phase-histogram aggregates, oMLX self-named rows), a per-request dispatch basis, and bounded persisted numeric history. `RoutingShadow` (passive), `cache-cost`, `cache-continuity-audit/-evidence`, `throughput`, `rate-peaks` are evidence/display-only layers.

## 2) Strengths

- **The forecast and the dispatcher provably share one chooser.** `completionEstimate` uses the same `queueChoice` as `schedule()`/`queuedChoice`, and I traced the subtle exhausted-turn case: `queueChoice` returns `clearAllocation: true` (queue-choice.mjs:24) which `completionEstimate` honors (routing-plan.mjs:49–50) before re-creating a fresh `{used:0}` allocation (routing-plan.mjs:70–74) — matching `schedule()`'s reset (gateway.mjs:1013–1016). Forecast/dispatch parity holds, and routing-plan.test.mjs:147–160 pins it.
- **Correct conditional estimator math.** `remainingOutputTokens` computes E[min(L,limit) − generated | L > generated] in log space without CDF subtraction (routing-estimates.mjs:60–93), verified term-by-term (Mills continued fraction, integrated exponential series, `logDifference`); a generation past its estimate keeps a *growing* conditional mean instead of vanishing — this structurally fixes prior-audit B3. Regression-tested against independent Python `erfc` values (routing-estimates.test.mjs:17).
- **Anti-fabrication discipline is consistent.** Unknown stays unknown: `running_progress_unavailable`, `basis_absent`/`basis_identity_mismatch`/`basis_stale` diagnostics (routing-observations.mjs:525–529), surplus engine work never becomes free capacity (routing-observations.mjs:560–578), aggregate engine throughput never becomes a request speed, and the 0.9-per-level guess is always outranked by measurements (`phaseSpeed` tier order, routing-estimates.mjs:149–167).
- **Evidence-tier labeling** (`SPEED_EVIDENCE_RANK`, routing-estimates.mjs:171–172) and decision receipts carrying per-lane failure reasons (`progressReason`, `basisReason`, `runningReasons`, DG-15 8 MiB signal, routing-observations.mjs:530–545, 606–640) make bad placements explainable from the record itself.
- **Durability hygiene:** atomic temp+rename+fsync with directory fsync in `AffinityStore.save` (gateway.mjs:163–172), corrupt routing history preserved without overwrite (routing-observations.mjs:116–131), restored speed rows parked and never mixed into live evidence.
- **Prior-audit fixes that verified as still holding:** B2a/B2c (wait-excluded per-request samples; cache subtracted once, routing-observations.mjs:486–487), B3 (conditional math above), M4 (turn reservations normalized into the forecast, routing-plan.mjs:17–34), M8 (single `queueBound`, gateway.mjs:413), M7's NaN/margin boundary tests (routing-plan.test.mjs:71–77).
- **Test depth in this area is unusually good:** margin boundary at exactly 30 s, close-arrival booking visibility, warm-cache vs. faster-peer tradeoffs, fast-lane overflow matrix, reservation normalization failures — all pinned.

## 3) Findings

1. **MEDIUM · bug** — `ds4-gateway/routing-observations.mjs:93` — `if (row.model !== undefined && row.model !== null && row.id === active.id && row.model === active.model) {`. Gateway running jobs never carry a `.model` property (the job literal at gateway.mjs:1585–1586 and dispatch never set one; repo-wide grep for `(active|job).model` finds only this comparison). So in the live path this branch can never match, `matched`/`taken` stay empty, and the promised guarantee — "Requests already matched by id are marked taken first, and those marks are never lent, so a row can never displace a real correlation" (comment at routing-observations.mjs:83–85) — does not hold. In a row set where `rows.length === running.length` but only *some* rows correlate via the direct find (`candidate.model === worker.model`, routing-observations.mjs:471 — note it compares against the *worker's* model, not the job's), a request already correlated by id can also be lent that same row positionally while another row goes unused: one request's progress is double-counted and another's dropped, breaking the lane-sum invariance the design leans on. The tests never set `model` on running jobs either (routing-observations.test.mjs uses rows with ids like `'engine-placeholder'`), so the branch is untestable as wired. **Remedy:** compute direct id correlations first and pass their row indices into `engineRowOrdering` as pre-taken (or match `row.model === workerModel` inside it).
2. **MEDIUM · bug (robustness)** — `ds4-gateway/routing-observations.mjs:491` — `let rateSamples=this.samples,concurrency=worker.native?.running ?? worker.running.length;`. `native.running` can be `0` while the gateway tracks in-flight work (a stale pre-dispatch gauge within the 5 s freshness window, or the same lifecycle race the surplus block explicitly tolerates). `0` is not nullish, so `concurrency=0` reaches `phaseSpeed`, which **throws** for `concurrency < 1` (routing-estimates.mjs:134–135: `throw new Error('Specify a phase and positive execution concurrency.')`). The throw escapes to the blanket `attempt` catch (routing-observations.mjs:173), aborting the **entire** `evaluate()` — the whole routing comparison for that tick is silently dropped (`errors++`), for all workers, not just the offended lane. Every sibling path guards this (`worker.running.length + 1` at :580; `Number.isSafeInteger(value.running) && value.running >= 1 ? value.running : jobs.length` in `observeEngineRows`), only this one doesn't. **Remedy:** `concurrency = Math.max(1, worker.native?.running ?? worker.running.length)`, or prefer the gateway count when the native gauge reads 0.
3. **MEDIUM · efficiency** — `ds4-gateway/gateway.mjs:550` — `relocation:{completed:...,offers:relocationOffers().length,...,genie_offers:genieRelocationOffers(),diagnostics:relocationDiagnostics(),...}`. In active mode (`timeRouting`) a single `stats()` call — served on `GET /gateway/status`, `GET /health`, and control `GET /workers` (`registry()`, gateway.mjs:1708 repeats offers+diagnostics) — triggers up to **96 full route comparisons**: `relocationOffers()` → `timeRoutingOffers()` (≤32 `evaluateRoutingTime`, gateway.mjs:683–696), `genieRelocationOffers()` → *another* `timeRoutingOffers()` (gateway.mjs:777–779), and `relocationDiagnostics()` → ≤32 more (gateway.mjs:744–746). Each `evaluateRoutingTime` rebuilds the whole worker snapshot (with a `canStartNow` preview per worker), normalizes every queued/running job via `request()` (which scans cached message-hash rows — see finding 9), and runs `completionEstimate` per worker — re-computing decisions the 1 s waiting tick (`rebalanceUndispatched`, gateway.mjs:818–821) just made. Dashboard polling turns this into a continuous estimator storm on the HTTP path. **Remedy:** compute `timeRoutingOffers()`/diagnostics once per stats() call and reuse; memoize decisions per state-revision for ~1 tick.
4. **MEDIUM · efficiency** — `ds4-gateway/routing-observations.mjs:645–659` — `const data = JSON.stringify({version: 1, outputs: this.outputs, samples: [...(this.restoredSamples ?? []), ...this.samples].slice(-4096)});`. Every `save()` re-serializes up to 4096 samples **plus** the parked, unchanging `restoredSamples`, then atomic-writes + fsyncs. `save()` fires on every request finish (`complete()`, :187) and at the end of every engine poll batch **even when nothing new was emitted** — `observeEnginePhases` (:385) and `observeEngineRows` (:446) end with unconditional `this.samples = this.samples.slice(-4096); this.save();` after their guard blocks, and `observeNative`'s gateway-id path (:312) likewise. At the 2 s telemetry cadence on a busy lane that is ~1 MB of stringify + write + fsync per poll with zero new evidence. **Remedy:** set a dirty flag only on actual appends and save on that; persist parked rows once (separately or epoch-gated) instead of re-writing them on every save.
5. **MEDIUM · tidy (needs verification of intent)** — `ds4-gateway/gateway.mjs:1520` — `trafficClass=geniePriority||req.headers['x-dsg-observer']==='gate-genie'?'genie':'unclassified';` and :1577 — `const genieFlexible=!key&&(geniePriority||(trafficClass==='genie'&&req.headers['x-dsg-review-flexible']==='1'));`. `geniePriority` is now key-gated (`isGenieRequest`), but `trafficClass='genie'` still comes from the unauthenticated observer header, so **any bearer-authenticated client** can claim the flexible fast path (`x-dsg-observer: gate-genie` + `x-dsg-review-flexible: 1`, no session key): immediate placement via `freeGenieNode` (gateway.mjs:935–939), bypassing queue placement, plus the `x-dsg-review-no-wait` advisory admission and preview suppression. This is precisely prior-audit blocker **B5**, and gateway.test.mjs:2846–2849 (`legacy:{'x-dsg-observer':'gate-genie','x-dsg-review-flexible':'1'}`) shows the path is *deliberately* retained and tested as an entry path. Impact is queue-jumping among already-authorized clients, not unauthorized access — but it contradicts the audit's verdict on record. **Remedy:** either gate `genieFlexible`/`trafficClass` promotion on `isGenieRequest` and retire the legacy headers, or document them explicitly as trusted-local legacy with the audit's B5 marked "accepted deviation."
6. **LOW · refactor (coherence)** — `ds4-gateway/routing-observations.mjs:243–446` — the four sampling paths (`observeNative` gateway-id deltas, `observeSerial`, `observeEnginePhases`, `observeEngineRows`) each re-implement overlapping guard chains with drifting thresholds: freshness `fresh(value.activity_at)` ≤5 s (:296) vs. interval `seconds <= 15` (:365) vs. `seconds <= 5` (:303); `running >= 1` requirements in three different spellings; identity/epoch invalidation repeated; and the `slice(-4096); save();` tail duplicated at :266, :312, :333, :385, :446. This is the accretion seam of the stack. **Remedy:** extract one "sampling interval" validator (prior/changed/connected/fresh/seconds) and one `pushSamples(rows)` owner of the slice+save+persist policy; keep the per-engine matchers thin.
7. **LOW · tidy (comment)** — `ds4-gateway/routing-observations.mjs:536–545` vs. `:547–558` — the surplus-work rationale is stated twice back-to-back; the first block ("Unmatched native work is not free capacity… the engine briefly reporting MORE running requests…") is the older wording of the second, more precise block. Delete the first; keep the bullet-form second.
8. **LOW · tidy** — `ds4-gateway/routing-estimates.mjs:14–16` vs. `ds4-gateway/routing-observations.mjs:123,180` — the finish-reason whitelists diverge: the fit accepts `['stop','tool_calls','function_call','end_turn','tool_use']` while the observer normalizes/stores `['stop','tool_calls','function_call','length','content_filter']`. The fit's `end_turn`/`tool_use` branches are unreachable from gateway-recorded rows, and censoring (`length`, `content_filter`) is only implicit in the fit's list. **Remedy:** export shared `MEASURED_FINISH_REASONS` / `CENSORED_FINISH_REASONS` from one module so a future route/observer change cannot silently desync fit censoring.
9. **LOW · efficiency** — `ds4-gateway/routing-observations.mjs:190–199` — `request()` runs a cache-prefix scan per queued/running job per evaluation: for each worker it filters ≤8 cached rows and compares up to 512 64-char message hashes per row (`row.messages.every((value, index) => value === metadata.messages[index])`). In active mode this runs for every candidate on every evaluate (≤32/s via the waiting tick, multiplied by the finding-3 storm). **Remedy:** memoize per `(identity, template, messages reference)` within one `evaluate()`, and short-circuit rows shorter than the current best match (rows are prefix-candidates only if `row.messages.length >= best.tokens-row` is plausible — or at least skip the `every` scan once a longer match exists).
10. **LOW · efficiency** — `ds4-gateway/gateway.mjs:139` — `count(node) { return Object.values(this.data.sessions).filter(s => s.node === node).length; }` is called inside `placementChoice`'s sort comparator (gateway.mjs:852–854: `store.count(a.id) - store.count(b.id)`) and per `candidate()` (gateway.mjs:697) — O(nodes·log nodes × sessions) full scans per admission and per flexible-Genie probe each second, growing with the number of conversation homes. **Remedy:** compute a `Map(node → count)` once per placement call (or maintain incremental counts in the store).
11. **LOW · tidy (test gap)** — `ds4-gateway/queue-choice.mjs` has **no direct unit test** (no `queue-choice.test.mjs`; only routing-plan/gateway tests touch it indirectly). Its most subtle semantics — the exhausted-turn masking branch at :20–24 (`priorityIndex(eligible.map(job => job.key === allocation.key ? {...job, cancelled: true} : job))` plus the rank-equality guard that lets a conversation continue beyond N only when no same-rank competitor exists), grace-expiry clearing, and `release` precedence — are exactly the logic a dispatcher change could silently break. **Remedy:** add a small direct test file covering: exhausted-with/without competitor, priority override of a reservation, blocked job + grace expiry, `release` vs `until` clearing.
12. **LOW · tidy** — `ds4-gateway/routing-plan.mjs:165–166` — inside `if (home?.eligible) {`, the check `if (home.completionSeconds === null) return … 'current_timing_unavailable'` is unreachable: this code is only reached when `eligible.some(c => c.completionSeconds === null)` was false (all eligible candidates timed, routing-plan.mjs:104–156 always returns), so an eligible home here is always timed. Harmless defense-in-depth, but it suggests a code path that cannot occur; either delete or comment it as a guard.
13. **LOW · tidy** — `ds4-gateway/gateway.mjs:719` — `if(count++>=32){shadow.state.skipped++;continue;}` increments the shadow's `skipped` counter even when the shadow is disabled (`evaluateShadow` no-ops via `observe`). Misleading telemetry only. **Remedy:** guard on `shadow.enabled`.

## 4) Top 5 proposals

1. **Kill the stats()/registry() evaluation storm (finding 3).** Compute time-routing offers/diagnostics once per read and memoize decisions per cheap state-revision for ~1 tick. *Effort: M. Risk: low* — receipts/`evidence_id` are derived from the decision, so a short TTL only risks offering a marginally older estimate, which `reconsiderRouting`'s revalidation already guards.
2. **Two small correctness fixes in the sampling seam (findings 1–2).** Clamp/repair the `concurrency` fallback and pass pre-correlated rows into `engineRowOrdering`. *Effort: S. Risk: low* — both are localized; add a test with a mixed correlated/uncorrelated row set and a `native.running=0` fixture.
3. **Dirty-flag persistence + parked-row separation (finding 4).** Only serialize on real appends; stop re-writing `restoredSamples` every save. *Effort: S–M. Risk: low* — the restore path already tolerates missing parked rows.
4. **Refactor `RoutingObservations` into per-source samplers over a shared interval-guard + sample-store (finding 6), and add `queue-choice.test.mjs` (finding 11).** This is the highest-leverage maintainability move in the area: it converts an accreted 660-line class with four overlapping guard dialects into testable units while freezing current semantics with characterization tests first. *Effort: L. Risk: medium* — sampling regressions silently starve the estimator, so land characterization tests before restructuring.
5. **Decide and document the legacy Genie flexible path (finding 5), and share the finish-reason whitelists (finding 8).** *Effort: S. Risk: low* — the decision is policy, not code volume; whichever way it goes, the audit ledger and the docs should agree with the tests.

## 5) Open questions / disagreements

- **Task/file mapping:** `cache-continuity.mjs` does not exist. The continuity seam splits into `continuity.mjs` (relocation receipts, rejections), `cache-continuity-audit.mjs` and `cache-continuity-evidence.mjs` (dashboard projection). I reviewed all three plus `cache-cost.mjs`; nothing in them rose to a finding beyond what's listed (the audit's barrier/budget logic is exceptionally careful).
- **`engineRowOrdering` invariance is conditional on `totalTokens`** (routing-observations.mjs:484): for prefill rows the request's input is replaced by the row's `totalTokens` (adapter fills it from `row.total`, endpoint-telemetry.mjs:173), making the pairing sum-invariant. If an oMLX build omits `total`, pairing swaps change the sum (request byte-estimates differ). Needs verification against a live oMLX `/admin/api/activity` payload — I could not confirm every deployment emits `total`.
- **Bytes/4 vs. engine token counts:** the byte-estimated `inputTokens` can undershoot engine `computedTokens` for multi-byte scripts (CJK ≈ 3 bytes/token vs. bytes/4), tripping `request_progress_inconsistent` (routing-estimates.mjs:210) and blinding a lane during prefill — the exact placement-loss class this stack exists to prevent. Worth one measurement on real traffic before dismissing.
- **Prior-audit residue:** M5 (priority aging formula) and M2 (sole-lane cap relaxation) are *not* implemented; `docs/queue-priority.md` documents unbounded higher-priority delay as intended ("There is no hidden automatic promotion"). B4's kill switch exists for margin/capacity but **not** for the routing mode itself — enabling/disabling `routing_time_enabled` still requires a restart (docs acknowledge Door-held replacement). Confirm these are accepted deviations, not omissions.
- **Single global output fit:** the audit's B2b (bimodal tool-loop outputs underestimating big turns) is only partially addressed — the fit is fleet-global, not per-class; a long agent-loop turn still reads short early in its decode. The docs flag censoring bias honestly; per-conversation/class fits would be the next lever but change estimator variance.
