# Deep Review — Cross-cutting Architecture & Maintainability (Star Gate / DSG)

Read-only audit. No files were modified. All findings verified by reading source; line numbers are from the current working tree.

## 1) System understanding

DSG is a zero-dependency Node (≥22.22.2, stdlib-only) local inference-fleet gateway. `ds4-gateway/` holds 253 `.mjs` files: 105 tests + 148 modules (147 siblings around `gateway.mjs`). Three long-running servers: **gateway core** (`gateway.mjs`, 2266 lines — affinity store, SSE-aware proxy, scheduler with priority/conversation turns, time-routing planner, quarantine, worker CRUD, ~40-route private Unix control socket), **Continuity Door** (`door.mjs`, 264 lines — byte-transparent hold/forward proxy that makes planned core replacement uneventful), and **dashboard** (`dashboard.mjs`, 560 lines — CSP-hardened same-origin UI server composing ~48 feature modules, plus `ui/` browser JS with `ui.js` at 1562 lines). CLI/lifecycle layer (`lifecycle.mjs`, `service-control.mjs` + thin `*.sh` exec wrappers) manages macOS LaunchAgents with drain-fencing, door-hold coordination, and state backups. `config.mjs` is the single config seam (paths resolved beside `config.local.json`). Domain families: `recovery-*`, `media-*`, `spark-*`, `routing-*`, `hermes-*`. Python satellites handle Docker/systemd recovery, serving and media ops. `gateway.mjs` and `dashboard.mjs` are imported only by tests; every other module is a leaf consumed by one of the three servers or a CLI.

## 2) Strengths

- **Genuinely dependency-free core.** `package.json` declares no runtime deps; engines pinned (`"node": ">=22.22.2"`); CI matrix (ubuntu/macos) pinned to that version (`.github/workflows/test.yml:9,14`). This is rare discipline for a project of this size.
- **The test suite is deep, not decorative.** `gateway.test.mjs` is 3,334 lines with a synthetic backend rig asserting security boundaries (bearer credential never forwarded — "DSG ingress credentials never cross the unauthenticated stock-DS4 boundary", encoded-path 404s, header stripping), byte preservation, no-replay semantics, quarantine and vision recovery. `dashboard.test.mjs` even evaluates the browser bundle with `vm` and validates that every `src/href` in `index.html` is served (`dashboard.mjs:91-93`). `scripts/check.mjs` syntax-gates every JS file and every shell script; `.githooks/pre-commit` runs privacy checks on staged files.
- **Startup/shutdown orchestration is careful and testable.** `lifecycle.mjs` separates `parseArgs/checkRuntime/backupControlState/lifecycle/portListening/formatResult` with injected `ops`, so orchestration is unit-tested (`lifecycle.test.mjs`) without touching launchd. `service-control.mjs` implements drain-fencing ("Fence admission before the final idle check"), door-hold coordination (`coordinatedCoreRestart/Park`), and refuses to overwrite unrelated registrations. Shell scripts are consistent thin `exec` wrappers.
- **Contract docs are accurate where they matter.** I verified `docs/simplified-system.md` (160-char preview, 64 MiB shared / 8 MiB per-request bounds, 5-minute affinity window = `gateway.mjs` `automaticAffinityWait ?? 300000`), `docs/queue-priority.md` (three classes, stale-edit conflicts = `job-priority.mjs`, `setJobPriority` in `gateway.mjs:442-455`), `docs/continuity-door.md` (hold/forward contract matches `door.mjs`), `docs/agent-api.md`, and `docs/priority-lens.md`/`docs/embeddings.md` (retired features clearly marked with redirects).
- **Durability engineering inside `gateway.mjs` is excellent**: PID + process-start-identity state locks (`gateway.mjs:99-105`), atomic temp-file + fsync + directory-fsync saves (`AffinityStore.save`), persist-before-relocation ordering with rollback ("Persist first. A failed write cannot strand the client between queues.", `gateway.mjs:676-691`), and engine-vs-transport failure discrimination for quarantine (`ENGINE_FAILURE_OUTCOMES`/`AMBIGUOUS_FAILURE_OUTCOMES`, `gateway.mjs:82-104`). Comments explain *why*, consistently.
- **Error/observability conventions are coherent**: services log structured JSON lines to stdout only (`gateway.mjs:86`), CLI tools use `console.*`, all gateway-owned error text is prefixed via `report.mjs:dsgReport`, and sanitizers (`safeGatewayEvent`, `safeManagementPath` in `dashboard.mjs:49-58`) bound what leaves the process.

## 3) Findings

**1. HIGH — bug (CI). `.github/workflows/test.yml:27`** — CI invokes an npm script that does not exist.
Evidence: `- run: npm run memory:test`, while `package.json` scripts contain no `memory:test` (its `hermes-memory.test.mjs` was folded into the main `test` list, `package.json:12`). `npm run` exits non-zero on a missing script, so every CI job fails at this step (after `npm test`/`continuity:test`/`data:test`).
Why it matters: CI is the only automated gate; either it is permanently red (masking real failures) or nobody watches it.
Remedy: delete the line (memory tests already run in `npm test`), or restore a `memory:test` script; then confirm a green run.

**2. HIGH — bug (test wiring). Five test files exist but are in no npm script.**
Evidence: `ds4-gateway/generation-health.test.mjs`, `reasoning-loop.test.mjs`, `state-lock.test.mjs`, `upstream-agent.test.mjs`, `fleet-catalogue.test.mjs` appear in no script in `package.json` (verified by grep over the whole file). Their targets are core: `generation-health.mjs` (quarantine observer, imported `gateway.mjs:30`), `reasoning-loop.mjs` (in-flight loop kill, `gateway.mjs:7`), `AffinityStore` (persistence/locking, `state-lock.test.mjs:6` imports it from `gateway.mjs`), `upstream-agent.mjs` (pool sizing, `gateway.mjs:16`). Related: `json-usage`/`throughput` run only under `data:test`, and `rate-peaks.test.mjs` runs solely as a side-effect import of `dashboard.test.mjs:17` (`import './rate-peaks.test.mjs';`).
Why it matters: regressions in quarantine, loop detection, or state locking ship undetected; CI green does not mean these pass.
Remedy: switch `test` to discovery (`node --test ds4-gateway/ examples/`) or add a guard script asserting every `*.test.mjs` is referenced; wire the five orphans immediately (S).

**3. HIGH — hygiene/efficiency. Unbounded backup accumulation, partly code-generated.**
Evidence: ten `gateway.mjs` mutation sites copy the whole store to a timestamped `.bak` with no retention, e.g. `gateway.mjs:1727` `const backup=\`${store.filename}.execution-capacity-${Date.now()}-${randomUUID()}.bak\`;fs.copyFileSync(store.filename,backup,...)` (also 1738, 1749, 1774, 1789, 1820, 1841, 1883, 1934, 1959). The working tree shows the result: `runtime/` holds 200+ `affinity.json.*.bak` files (≈90 from one `media-setup` day), ~100 `genie-*-backup-*` directories, 25+ `gateway-reload-*.log`, and — worst — **source-code snapshots inside runtime/**: `runtime/gateway-before-shared-context-1789788760.mjs`, `runtime/routing-observations.mjs.original-HEAD.bak`, `runtime/dashboard.mjs.bak-includelegacy-20261009T184433`, `runtime/model-admission-test-before-shared-1789788952.mjs`. Repo root adds 22 config snapshots (`config.local.json.bak-2026…`, 21 dated + `config.local.json.pre-m3-probe-fix-bak`), all containing live endpoint/credential-path config (git-ignored via `**/config.local.json*`, `**/*.bak*`, but present on disk).
Why it matters: incident response burrows through hundreds of near-identical files; disk growth is unbounded; code copies in `runtime/` rot silently and can be resurrected by mistake.
Remedy: centralize mutation backups in one `AffinityStore.backupBefore(kind)` helper with a retention cap (keep last N per kind, prune older); add a `scripts/prune-runtime.mjs` (dry-run first) for `*.bak` and `genie-*-backup-*`; delete (or archive outside the tree) the code snapshots; move root config backups into `backups/config-local/` (that directory already exists) and adopt `lifecycle.mjs:backupControlState` (manifested, dated dirs) as the only convention.

**4. HIGH — doc accuracy (tidy). README advertises removed surfaces; broken links in four docs.**
Evidence: README links `docs/genie-memory.md` (lines 49, 153), `docs/genie-conversation.md` (56, 384), `docs/genie-telegram.md` (386), `docs/genie-studies.md` (110) — none exist (`find docs/genie-*.md` → no matches); README:58 says `npm run genie:demo` — not in `package.json`; README's setup section says "Normal setup also installs its own pinned Hermes and Python for conversational Genie" while `scripts/setup.mjs:6` prints "legacy Genie has been removed" and `setup.mjs:12-13` sets `genie:false`, deletes `genie_chat`. Same drift in `docs/observer.md:50` (→ `genie-memory.md`), `docs/installation.md:33` (→ `genie-conversation.md`), `docs/current-work-plan.md:16` (→ `genie-recipe-trials.md`, missing). The README's own top banner ("The legacy Genie agent, Telegram bridge … have been removed") contradicts ~40 later lines describing those features as current.
Why it matters: this repo's docs are otherwise its best asset; here an agent or new operator will follow setup instructions that cannot work, and the internal contradiction undermines trust in every other claim.
Remedy: one sweep commit: either restore the four genie docs or rewrite the affected README/installation/observer/current-work-plan sections for the gateway-only build; add a link-existence check to `scripts/check.mjs` (S).

**5. MEDIUM — efficiency. `stats()` and `registry()` recompute the routing planner on every poll.**
Evidence: `gateway.mjs:550` — `stats()` computes `offers:relocationOffers().length, … genie_offers:genieRelocationOffers(), diagnostics:relocationDiagnostics()`; `genieRelocationOffers()` (777-783) calls `relocationOffers()` again; `relocationDiagnostics()` (744) re-runs `evaluateRoutingTime` per queue head (up to 32). `GET /gateway/status` is polled every 2 s (`dashboard.mjs:555` `const interval = setInterval(poll, 2000)`), and `GET /health` also serves `stats()`. Worse, `registry()` (`gateway.mjs:1714-1715`) does `workers: nodes.map(n => ({ ...definition(n), ...stats().workers.find(w => w.id === n.id), … }))` — one **full** `stats()` computation per worker per call, so a 20-worker `/workers` call runs the entire status+planner pipeline 20 times.
Why it matters: O(nodes²) work on the hottest polling path; with time-routing enabled each poll evaluates the planner dozens of times regardless of change.
Remedy: memoize the `stats()` payload for ~250-500 ms; in `registry()`, compute `stats()` once and index by id; consider a cheap "diagnostics stamp" so `relocationDiagnostics()` is reused across offers/genie-offers within a tick.

**6. MEDIUM — refactor (layering). `gateway.mjs` is a module-graph hub; `AffinityStore` and `UsageObserver` should not live there.**
Evidence: `state-lock.test.mjs:6` `import {AffinityStore} from './gateway.mjs';` and `json-usage.test.mjs:27` `import {UsageObserver} from './gateway.mjs';` — unit tests for a store and an SSE parser must load the entire 57-import module graph (and construct nothing else). `AffinityStore` spans `gateway.mjs:109-176` plus `processStartedAt` (99-105) and operator-action validation (77-80); `UsageObserver` spans 180-338 and is otherwise self-contained (uses `output-shape`, `StringDecoder`).
Why it matters: every future module that needs durable state inherits gateway's import cost and cycle risk; the store is the natural first extraction.
Remedy: extract `state-store.mjs` (AffinityStore + lock identity + validation) and `usage-observer.mjs`; re-export from `gateway.mjs` temporarily if desired. Low risk — both are covered by existing tests.

**7. MEDIUM — refactor. The control-route surface is hand-synced in three places.**
Evidence: the allowlist array at `gateway.mjs:2052` (≈40 route strings), the client-side allowlist `Set` at `worker-client.mjs:2`, and the dashboard action map at `dashboard.mjs:536-540` (`({'media-eligibility':'/media-host-eligibility','job-priority':'/set-job-priority',…})[action]`). `worker-client.mjs` rejects unknown paths, so a route added to the core but missed in the client set silently breaks the dashboard action; timeouts are special-cased ad hoc (`route==='/genie-media-audit'?90000:30000`, `worker-client.mjs:15`).
Why it matters: the control plane grows every release (recovery, media, capacity, agents); triple-maintenance is how drift happens.
Remedy: one exported `CONTROL_ROUTES` table (name, method, timeout, mutating?) imported by `gateway.mjs`, `worker-client.mjs`, and `dashboard.mjs`.

**8. LOW/MEDIUM — refactor. Duplicated proxy/socket plumbing.**
Evidence: hop-header stripping duplicated — `gateway.mjs:87-91` (`hopHeaders`/`forwardHeaders`) vs `door.mjs:15-16` (`hopHeaders`/`headers`); JSON/error responders duplicated (`gateway.mjs:93-97` vs `door.mjs:17-19`); two divergent unix-socket JSON clients — `door-client.mjs` (no timeout, no size cap) vs `worker-client.mjs` (30/90 s timeout, 1 MiB cap, channel header).
Why it matters: the Door is the byte-transparency boundary; a fix to header handling in one copy can miss the other.
Remedy: a small `proxy-http.mjs` (hop headers, JSON responder, `invalidHttp`) and one `control-client.mjs` with per-route options.

**9. MEDIUM — tidy/hygiene. Repo-root clutter of one-off operational artifacts.**
Evidence: root contains 5 `admit-*.mjs` one-off admission scripts (e.g. `admit-ds41f-m3.mjs:1-9`, self-described "NOT yet run"), `.hermes-mic-check.py`, `pickuphere.md`, `DSG-V6-STATUS-2026-09-18.md`, `GENIE-HERMES-FORK-FIXLIST-2026-09-27.md`, `Gate-Genie-Embedded-Hermes-Fork-Plan-v0.2.md`, `gateway-logs.sh`/`gateway-status.sh` (fine), plus `tmp/` and `kanban/` — all git-ignored (`.gitignore` covers `admit-*.mjs`, the two Genie MD patterns, `tmp/`, `plans/`), so this is working-tree hygiene, not repo pollution.
Why it matters: agents and operators grep the root; one-off scripts that mutate the fleet sitting beside shipped entry points invite accidental execution and stale-copy confusion.
Remedy: an ignored `ops/` directory for `admit-*.mjs` and status notes; delete superseded copies after owner confirmation.

**10. LOW — efficiency/portability. Hardcoded `/bin/ps`.**
Evidence: `gateway.mjs:90-96` `execFileSync('/bin/ps', ['-p', String(pid), '-o', 'lstart='], …)` inside `processStartedAt`, used by the `AffinityStore` lock. Fine on macOS; on Linux without merged `/usr` (`/bin/ps` absent — needs verification per distro) lock-takeover identity checks would throw `ENOENT`.
Why it matters: the README supports Linux (`npm start` under a service manager); the failure would surface only during stale-lock recovery — the worst time.
Remedy: resolve `ps` via PATH with a `/proc/<pid>/stat` starttime fallback on Linux. Needs verification on a target distro before changing.

**11. LOW — tidy (test naming). Test names that match no module weaken the 1:1 convention.**
Evidence: `media-submit.test.mjs`, `model-admission.test.mjs`, `observer.test.mjs`, `door-forwarding.test.mjs`, `serving-checks-integration.test.mjs`, `dashboard-overhead.test.mjs`, `pi-*-contract.test.mjs`, `install.test.mjs` (no `install.mjs`; it tests config/setup) — while ~100 other tests are exactly `<module>.test.mjs`. This inconsistency is what allowed finding #2 to happen unnoticed.
Remedy: rename to `gateway-admission.test.mjs`, `gateway-observer.test.mjs`, etc., or add a short `docs/testing.md` mapping table when introducing the discovery-based runner.

**12. LOW — tidy. Duplicated one-off "runner" scripts with copy-paste conventions.**
Evidence: `film-runner.mjs:15-25` (own `ssh()`/`controlRequest()`/`save()` helpers), `media-pair-direct.mjs` and `media-pair-runner.mjs` (same pattern, "Pair lifecycle + restoration precautions preserved from media-pair-runner", `media-pair-direct.mjs:6`), `media-runner.mjs:10-14` (yet another `execute/quote/remote/save` set). None is imported; each is spawned per operation folder.
Why it matters: receipt/atomic-save conventions (mode-0600, tmp+rename) are security-relevant and currently re-implemented four times.
Remedy: extract a small `runner-kit.mjs` (ssh exec, control request, atomic receipt save) and move the four runners to `scripts/` or `ds4-gateway/runners/` (M, low risk — behavior-preserving).

## 4) Top 5 proposals

1. **Make CI truthful and complete** (S, low risk): fix `memory:test` (test.yml:27), adopt discovery-based test running with an "every test file is wired" guard, add `operations:test`/`spark:test` Python suites (or a documented exclusion). This converts the existing deep suite into an actual safety net.
2. **Extract the first two modules out of `gateway.mjs`** (S–M, low risk): `state-store.mjs` (AffinityStore + lock identity, `gateway.mjs:99-176`) and `usage-observer.mjs` (180-338). Establishes the layering pattern (L0 util → L1 store → L3 domain → L4 servers) and lets tests import without the full graph.
3. **Single control-route table + merged control client** (M, medium risk): one `CONTROL_ROUTES` source of truth for `gateway.mjs:2052`, `worker-client.mjs:2`, `dashboard.mjs:536`; merge `door-client`/`worker-client` with per-route options. Kills the whole class of three-place drift as the control plane keeps growing.
4. **Backup retention + runtime pruning policy** (S–M, low risk): `AffinityStore.backupBefore(kind)` with per-kind retention; `scripts/prune-runtime.mjs` (dry-run default) for `*.bak`/`genie-*-backup-*`; relocate or delete code snapshots in `runtime/`; consolidate root config backups into `backups/config-local/`. Keeps `runtime/` an operational asset instead of an landfill.
5. **Doc reconciliation sweep with automated link check** (S, low risk): resolve the genie-doc question (restore or rewrite), fix `genie:demo`, add link-existence validation to `scripts/check.mjs` so doc rot — the one place this repo's discipline currently breaks — is caught by the same gate that catches syntax.

*(Deferred, deliberately: extracting the dispatch/rewrite/vision-recovery pipeline from `gateway.mjs:1100-1470` is the highest-value long-term split but L effort and high risk; it should follow the route-table and registry extractions, leaning on the existing `gateway.test.mjs` rewrite-path regression tests ("Rewritten uploads stop leaking a phantom second request", CHANGELOG 2026-10-05).)*

**Target architecture (one line per layer):** L0 pure utils (`report`, `deadline`, `job-priority`, `queue-choice`, `request-auth`, `output-shape`, …) → L1 config/stores (`config`, `worker-config`, **`state-store` (new)**, `dataset`, `testing-mode`, `lan-sharing`) → L2 transport/clients (`endpoint`, **`control-client` (merged)**, telemetry collectors) → L3 domain families (`recovery-*`, `media-*`, `spark-*`, `routing-*`, `fleet-*`) → L4 servers (`gateway.mjs` slimmed to HTTP+scheduler+route table, `door.mjs`, `dashboard.mjs`) → L5 CLI/lifecycle (`lifecycle`, `service-control`, workers/agents/audit CLIs). Merge: door/worker clients, the four runner scripts. Delete (after owner confirmation): root `config.local.json.bak-*`, `admit-*.mjs` superseded copies, runtime code snapshots.

## 5) Open questions / disagreements

1. **Was the genie-doc removal intentional?** The README banner, `setup.mjs`, and `.gitignore` (`Gate-Genie-…-Plan-*.md`, `GENIE-HERMES-FORK-FIXLIST-*.md`) say the transition is deliberate, yet the dashboard still ships `hermes-brain/memory/profile` stores and their tests, and the README body still sells Genie features. Someone with product context must pick the direction for finding #4.
2. **Is CI actually running?** The `memory:test` mismatch implies a red or ignored workflow. I could not run `git log`/Actions checks (read-only mandate, no bash tool available to me); a supervisor should check the last workflow runs and when `memory:test` disappeared from `package.json`.
3. **`operations:test` and `spark:test` absent from CI** — intentional (slow, python-heavy) or oversight? They are the only runners for the `docker_profile*`/`serving_*`/`image_peer_transfer` suites.
4. **`/bin/ps` on Linux** (finding #10) needs a real distro check before I'd call it a bug rather than a smell.
5. **Deployment-risk note, not a code bug:** the live `config.local.json` uses `api_key: "none"` with `host: 0.0.0.0` — a documented home-LAN posture (README: "This route advertises the constant home-LAN key `none`"; `request-auth.mjs:14-16` treats `"none"` as the literal bearer token). Combined with finding #3's root-level config backups containing live credential *paths*, the local blast radius of a stray file read is larger than it looks.
6. **Where I suspect other areas own the real fix:** the 2 s dashboard poll (`dashboard.mjs:555`) is what *triggers* the `stats()` recomputation cost (finding #5); the gateway-side memoization is the right fix, but if dashboard poll volume ever grows, the poll design itself is the lever. Similarly, any flakiness attributed to "agent-made backups" in `runtime/` traces back to the gateway's own unretained backup code path (finding #3), not to the agents.

**Merge verdict for the area as a whole:** OK with notes — the architecture is sound and unusually well tested for its size; the blocking items before any release/PR train are the CI script mismatch (#1) and the unwired core tests (#2), both S-effort fixes.
